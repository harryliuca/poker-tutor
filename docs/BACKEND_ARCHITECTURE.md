# Backend Architecture

## Overview

Backend built on **Supabase** for:
- PostgreSQL database
- Authentication (Google OAuth)
- RESTful API (PostgREST)
- Real-time subscriptions (optional future feature)
- Row Level Security (RLS)

## Architecture Components

### 1. Supabase (Backend-as-a-Service)

**Why Supabase:**
- Free tier (up to 500MB database, 50,000 monthly active users)
- Built-in authentication with Google OAuth
- Automatic REST API generation from database schema
- Row Level Security for data protection
- Real-time capabilities for future features
- TypeScript client library

### 2. Authentication Flow

```
User → Mobile App → Google Sign-In → Supabase Auth → JWT Token → App
```

**Implementation:**
```typescript
// In mobile app
import { createClient } from '@supabase/supabase-js'

const supabase = createClient(SUPABASE_URL, SUPABASE_ANON_KEY)

// Google Sign-In
const { data, error } = await supabase.auth.signInWithOAuth({
  provider: 'google',
  options: {
    redirectTo: 'pokertutor://auth/callback'
  }
})

// Session management (automatic)
supabase.auth.onAuthStateChange((event, session) => {
  if (session) {
    // User is logged in
    const userId = session.user.id
    const email = session.user.email
  }
})
```

**User Creation:**
- On first login, trigger creates profile in `profiles` table
- Initialize stats (streak = 0, score = 0)
- Store Google profile info

```sql
-- Trigger to create profile on signup
CREATE OR REPLACE FUNCTION public.handle_new_user()
RETURNS TRIGGER AS $$
BEGIN
  INSERT INTO public.profiles (id, email, display_name, avatar_url, google_id)
  VALUES (
    NEW.id,
    NEW.email,
    NEW.raw_user_meta_data->>'full_name',
    NEW.raw_user_meta_data->>'avatar_url',
    NEW.raw_user_meta_data->>'sub'
  );
  RETURN NEW;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

CREATE TRIGGER on_auth_user_created
  AFTER INSERT ON auth.users
  FOR EACH ROW EXECUTE FUNCTION public.handle_new_user();
```

**Get Random Question**
```typescript

  .from('questions')
  .select('*')
```

## Supabase Edge Functions

For complex logic that can't be handled by RLS or client-side code.

### 1. Generate Daily Challenge Function

**Location:** `supabase/functions/generate-daily-challenge/index.ts`

```typescript
import { serve } from 'https://deno.land/std@0.168.0/http/server.ts'
import { createClient } from 'https://esm.sh/@supabase/supabase-js@2'

serve(async (req) => {
  const supabaseClient = createClient(
    Deno.env.get('SUPABASE_URL') ?? '',
    Deno.env.get('SUPABASE_SERVICE_ROLE_KEY') ?? ''
  )

  const today = new Date().toISOString().split('T')[0]

  // Check if challenge already exists
  const { data: existing } = await supabaseClient
    .from('daily_challenges')
    .select('id')
    .eq('challenge_date', today)
    .single()

  if (existing) {
    return new Response(JSON.stringify({ message: 'Challenge already exists' }), {
      status: 200
    })
  }

  // Select 10 questions (mix of difficulties and categories)
  // 3 beginner, 4 intermediate, 3 advanced
  // Distributed across categories
  const questions = await selectBalancedQuestions(supabaseClient)

  // Create challenge
  const { data, error } = await supabaseClient
    .from('daily_challenges')
    .insert({
      challenge_date: today,
      question_ids: questions.map(q => q.id)
    })

  return new Response(JSON.stringify({ success: true }), {
    headers: { 'Content-Type': 'application/json' },
    status: 200
  })
})
```

**Cron Job:** Run daily at 00:00 UTC to generate next day's challenge

## Security

### Row Level Security (RLS)

All tables have RLS enabled:
- Users can only read/write their own data
- Questions are read-only for authenticated users
- Daily challenges are read-only for authenticated users

### API Security

1. **Authentication Required**: All requests require valid JWT token
2. **Rate Limiting**: Supabase built-in (can configure limits)
3. **CORS**: Configured for mobile app domain only
4. **Service Role Key**: Never exposed to client (only in Edge Functions)

### Environment Variables

```env
# Public (safe to expose in mobile app)
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_ANON_KEY=eyJhbGc...

# Private (server-side only)
SUPABASE_SERVICE_ROLE_KEY=eyJhbGc... (never expose!)
```

## Data Flow Examples

### Daily Challenge Flow

```
1. User opens app
2. App fetches today's challenge from daily_challenges
3. If not exists, app calls generate-daily-challenge Edge Function
4. App fetches questions using challenge.question_ids
5. User answers questions one by one
6. Each answer:
   - Insert into user_answers
   - Update user_daily_progress
   - Call update-stats Edge Function
7. After completion:
   - Update profiles.current_streak
   - Mark challenge as completed
```

### Random Practice Flow

```
1. User selects "Practice"
2. App calls get-next-question Edge Function
3. Function returns question based on adaptive difficulty
4. User answers
5. Insert into user_answers (practice_mode = 'random_practice')
6. Update user_category_stats
7. Show next question
```
